# Черным по белому — сайт + админка

Лендинг порошковой покраски металла. React 19 + Vite + TypeScript + Tailwind.
Весь текст и изображения редактируются через админку, заявки с форм улетают в CRM.

## Запуск локально

```bash
npm install
npm run dev      # http://localhost:3000
npm run build    # сборка в ./out
```

## Админка

- Адрес: **`/admin`** (на проде — `https://<домен>/admin`).
- Вход по email + паролю (Supabase Auth).
- Меняет **весь** контент: логотип, меню, Hero, «О компании», преимущества,
  галерею, прайс, отзывы, блок заявки, подписи формы, контакты и футер.
  Картинки можно загружать файлом (в Storage) или указывать ссылкой.
- Контент хранится одним JSON-документом в таблице `public.site_content`
  (проект Supabase `chpb-site`). Значения по умолчанию — в
  `src/content/defaults.ts`; при загрузке они «подмешиваются», поэтому сайт
  работает даже без сохранённого контента.

## Архитектура контента

- `src/content/types.ts` — структура контента (`SiteContent`).
- `src/content/defaults.ts` — исходные тексты/изображения.
- `src/content/ContentContext.tsx` — провайдер: грузит документ из Supabase,
  мёржит с дефолтами, отдаёт через `useContent()`.
- Компоненты страницы читают только из `useContent()`.

## Заявки → CRM

Форма заявки и форма подписки отправляют `POST` (JSON) на публичную
Supabase Edge Function **`lead-intake`** (в проекте CRM `crm-v3`).
Функция кладёт лид в `public.leads` со `status = 'new'`, `source = 'website'`,
`owner_id = 1` — он сразу виден в списке лидов и в первой колонке канбана.

Ключи CRM в браузер не попадают: функция развёрнута с `verify_jwt = false` и
использует service-role ключ только на сервере. Исходник — в
`supabase/functions/lead-intake/index.ts`.

## Переменные окружения (необязательно)

Публичные значения уже зашиты в `src/lib/config.ts`, поэтому сайт собирается
без настройки. При желании их можно переопределить:

| Переменная | Назначение |
|---|---|
| `VITE_SUPABASE_URL` | URL проекта `chpb-site` |
| `VITE_SUPABASE_ANON_KEY` | anon-ключ `chpb-site` (публичный, защищён RLS) |
| `VITE_LEAD_INTAKE_URL` | URL функции приёма заявок |

> Никогда не кладите сюда service-role ключ — только публичный anon-ключ.
